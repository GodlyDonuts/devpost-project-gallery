# Devpost Hackathon Project Galleries

An **unofficial, community-run** set of project galleries for Devpost hackathons.
Devpost doesn't publish the official gallery until a couple weeks after the
deadline, so this collects submissions from each hackathon's participant list and
sorts them into that hackathon's tracks.

Built with plain HTML/CSS/JS (no build step) and hosted free on **GitHub Pages**.
A scheduled GitHub Action scrapes Devpost (resumably) and commits fresh data per
hackathon.

---

## How it's organized

Each hackathon is a manifest entry in `data/hackathons.json` and gets its own
data file `data/<slug>.json`. The landing page (`index.html`) lists every
hackathon so a visitor can pick which one to browse.

```
data/
  hackathons.json          # manifest: one entry per hackathon
  openai-build-week.json   # projects for that hackathon (generated by scraper)
  .scrape_state_openai-build-week.json   # crawler checkpoint (gitignored)
```

```
Devpost participants (login-gated)
        │  enumerate /participants?page=N
        ▼
  ~46k participant handles
        │  for each: fetch devpost.com/<handle>
        ▼
  user's public projects (software/<slug>)
        │  for each: fetch the project page
        ▼
  keep only projects "Submitted to <Hackathon>"
  classify into that hackathon's tracks
        ▼
  data/<slug>.json  ──►  gallery.html?h=<slug>
```

The scraper is fully **resumable** per hackathon: it checkpoint every page, so
you can run it in chunks or let the cron job pick up where it left off.

## Adding a new hackathon

1. Add an entry to `data/hackathons.json`:

   ```json
   {
     "slug": "my-hackathon",
     "name": "My Hackathon",
     "hackathon_id": "12345",
     "categories": ["Track A", "Track B"],
     "generated_at": null,
     "count": 0
   }
   ```

2. Create `data/my-hackathon.json` (can be empty — the scraper fills it):

   ```json
   {"slug":"my-hackathon","name":"My Hackathon","hackathon_id":"12345",
    "generated_at":null,"categories":["Track A","Track B"],"count":0,"projects":[]}
   ```

3. Run the scraper (it auto-detects the new entry), or trigger the workflow
   with `hackathon_slug=my-hackathon`.

That's it — the landing page picks it up automatically.

## Local preview

```bash
python3 -m http.server 8000
# open http://localhost:8000        (landing page)
# open http://localhost:8000/gallery.html?h=openai-build-week
```

The pages read `data/hackathons.json` and `data/<slug>.json`. With the seed
files they show empty states; once the scraper runs, cards appear.

## Running the scraper

### 1. Install deps
```bash
pip install requests beautifulsoup4
```

### 2. Get a Devpost session cookie (REQUIRED)
The participant list is **login-gated** ("Please log in to browse this hackathon's
participants."). Log in to Devpost in a browser, then copy the full `Cookie`
header from a request to `openai.devpost.com/participants` (DevTools → Network).

### 3. (Recommended) Use a proxy
46k+ participants means 100k+ requests. Use a proxy pool to avoid IP bans.
`PROXY_URL` accepts a single URL or comma-separated list.

### 4. Run
```bash
export DEVP0ST_SESSION_COOKIE="session=...; _devpost=..."
export PROXY_URL="http://user:pass@host:port"      # optional but recommended
python3 scrape.py                                   # all hackathons in manifest
HACKATHON_SLUG=openai-build-week python3 scrape.py  # just one
```

Useful env vars: `START_PAGE`, `MAX_PAGES` (0 = unlimited), `PAGE_DELAY` (seconds).

Resume automatically: re-run the same command — it skips already-processed handles.

## Deploy to GitHub Pages

1. Push this repo to GitHub.
2. **Settings → Pages → Source: Deploy from a branch**, branch `main`, folder `/ (root)`.
3. Add two **Repository Secrets** (Settings → Secrets and variables → Actions):
   - `DEVP0ST_SESSION_COOKIE` — your logged-in cookie.
   - `PROXY_URL` — your proxy endpoint(s).

The `scrape.yml` workflow runs hourly, appends to each `data/<slug>.json`, updates
`data/hackathons.json` counts, and commits. GitHub Pages serves automatically.

> ⚠️ **Cookie expiry:** Devpost session cookies expire. If a site stops updating,
> refresh the cookie and update the secret (or re-run via `workflow_dispatch`).

## Notes & caveats

- **Unofficial.** Not affiliated with OpenAI or Devpost. Respect Devpost's ToS;
  use a proxy and conservative delays to avoid hammering their servers.
- **Coverage depends on Devpost.** Submissions are only visible once the official
  gallery is published; the scraper backfills automatically after that.
- **Classification** uses whichever of the hackathon's track labels appears on the
  project page. If none match, it falls back to `Uncategorized` (still shown via "All").
